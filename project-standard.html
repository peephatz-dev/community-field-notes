ทำ Case ให้มีหลักฐาน

ใช้ Case Booklet เป็นกรอบร่วมของทีม ตั้งแต่เลือกพื้นที่และ Challenge ไปจนถึงตรวจความพร้อมของ Solution, PoC, ผลกระทบ ESG และชิ้นงานที่จะส่ง หน้านี้สรุปสาระสำคัญพร้อมระบุว่าอะไรเป็นข้อกำหนดตามเอกสาร และอะไรเป็นวิธีทำงานของทีมวิจัย

เริ่มใช้เกณฑ์กลาง ↓อ่าน Case Booklet ทั้งเล่ม
หลักการตัดสินใจร่วม

เริ่มจากปัญหาที่ตรวจสอบได้

หลักฐาน → บริบท → ยืนยันกับผู้ได้รับผลกระทบ → วิเคราะห์สาเหตุ → unmet need → แนวคิดและการทดลอง

ห้ามกระโดดจากโพสต์หรือภาพชิ้นเดียวไปสรุปต้นเหตุหรือออกแบบเทคโนโลยี

ข้อกำหนดพื้นที่และ ChallengeวิธีวิจัยCase CanvasESG และตัวชี้วัดชิ้นงานส่งตรวจความพร้อม
01 / PROGRAM REQUIREMENTS

ข้อกำหนดที่ใช้คัดกรองโครงการ

รายการต่อไปนี้สรุปจาก Case Booklet และข้อมูลแบบฟอร์มที่รวมอยู่ในเอกสาร โปรดตรวจแบบฟอร์มและประกาศล่าสุดก่อนสมัครหรือยืนยันเงื่อนไข เพราะผู้จัดอาจปรับข้อมูลได้

คุณสมบัติทีม

  • สมาชิกทีม 3–5 คน และหนึ่งคนสมัครได้เพียงทีมเดียว
  • สมาชิกทุกคนอายุ 18–35 ปี ณ วันสุดท้ายของการรับสมัคร
  • สมาชิกทุกคนพักอาศัยในประเทศไทยตลอดโครงการ
  • ผลงานต้องเป็นของทีม ไม่ละเมิดทรัพย์สินทางปัญญา
อ้างอิง: ตารางคุณสมบัติใน Case Booklet

แนวทางเลือกและพัฒนา Solution

  • เลือกพื้นที่หนึ่งแห่ง แล้วระบุ Challenge ที่ชัด
  • Solution ต้องสอดคล้องกับบริบทพื้นที่และผู้ได้รับผลกระทบ
  • ควรมีหลักฐานความเป็นไปได้ เช่น prototype, ผลทดลอง หรือข้อมูลสนับสนุน
  • อธิบายเส้นทางไปสู่การใช้จริง และตรวจผลกระทบข้างเคียงต่อชุมชน
ข้อกำหนดโครงการที่สรุปจากเอกสารแนบ
สถานะของข้อมูล: เกณฑ์หน้านี้ถอดความจาก Case Booklet ที่ผู้ใช้ให้มา ไม่ใช่ประกาศทางการฉบับที่ตรวจสอบกับผู้จัด ณ วันที่เผยแพร่ วันปิดรับสมัครและเงื่อนไขล่าสุดจึงต้องยืนยันจากประกาศ/แบบฟอร์มทางการ
02 / PLACE & CHALLENGE

พื้นที่ตั้งต้นและสามธีมของโครงการ

โจทย์ในตารางเป็น Challenge baseline ตาม Case Booklet ใช้ตั้งคำถามวิจัย ไม่ใช่ข้อยืนยันว่าปัญหา สาเหตุ หรือความต้องการเกิดขึ้นจริงในระดับหมู่บ้านแล้ว

พื้นที่โจทย์ตั้งต้นใน Case Bookletสิ่งที่ต้องตรวจต่อ

ปลุกของดี

เพิ่มมูลค่าอัตลักษณ์ วัตถุดิบ ภูมิปัญญา สินค้า หรือการท่องเที่ยวเชิงวัฒนธรรม

ตรวจความสอดคล้อง: ใครเป็นเจ้าของความรู้ ใครสร้างมูลค่า และรายได้คืนสู่ชุมชนอย่างไร

ปกป้องชุมชน

เสริมความปลอดภัย สุขภาวะ ความมั่นคงด้านน้ำ อาหาร สาธารณูปโภค และคุณภาพชีวิต

ตรวจความสอดคล้อง: ใครได้รับผลกระทบจากความเสี่ยงหรือช่องว่างบริการ และชุมชนเตรียมพร้อมอย่างไร

ปรับตัวฝ่าวิกฤต

เพิ่มความสามารถพึ่งพาตนเองและปรับตัว เช่น ทางเลือกพลังงานที่ยั่งยืนเมื่อเกี่ยวข้อง

ตรวจความสอดคล้อง: วิกฤตใดต้องรับมือ ความสามารถใดจำเป็น และทางเลือกก่อผลกระทบอย่างไร

03 / RESEARCH WORKFLOW

กระบวนการกลางของงานวิจัย

ลำดับนี้ถอดจาก Case Booklet และใช้เป็น workflow ร่วมของเว็บไซต์ เพื่อให้ทุกพื้นที่ผ่านเกณฑ์ชุดเดียวกันโดยไม่บังคับให้มีวิธีแก้แบบเดียวกัน

01 · สำรวจทำแผนที่เพจ กลุ่มอาชีพ หน่วยงาน องค์กร และผู้มีประสบการณ์ตรง
02 · เก็บหลักฐานบันทึก URL วันที่ ผู้โพสต์ พื้นที่ ภาพ/ข้อความ และความเชื่อมั่น
03 · ตรวจบริบทเทียบฤดูกาล นโยบาย งบ โครงการ เทศกาล และสภาพอากาศ
04 · วิเคราะห์ทำ causal chain ตั้งคำอธิบายอื่น และหาหลักฐานหักล้าง
05 · สังเคราะห์ทำ workflow ผู้เกี่ยวข้อง วิธีเดิม จุดติดขัด และ unmet need
06 · ทดสอบสัมภาษณ์ ทดลอง หรือวัดภาคสนามก่อนกล่าวอ้างผลกระทบ

ยืนยันแล้ว

มีการวัดหรือเอกสาร และแหล่งอิสระสอดคล้องกัน ระบุขอบเขตและช่วงเวลา

มีหลักฐานสนับสนุน

หลายสัญญาณท้องถิ่นสอดคล้อง ใช้คำว่า “หลักฐานชี้ว่า” พร้อมข้อจำกัด

สมมติฐาน

เห็นรูปแบบที่เป็นไปได้ แต่ยังพิสูจน์ห่วงโซ่เหตุไม่ได้ ต้องทดสอบต่อ

ยังไม่ทราบ

ข้อมูลไม่พอ ขัดแย้ง หรือระบุไม่ได้ เก็บเป็นคำถาม ไม่ใช้เป็นข้อกล่าวอ้าง

หลักฐาน Facebook: ใช้เป็นสัญญาณค้นหาและทำความเข้าใจภาษาหรือเหตุการณ์ ห้ามใช้จำนวนโพสต์แทนความชุก และห้ามอนุมานสาเหตุจากรูปลักษณ์หรือความสัมพันธ์อย่างเดียว
04 / CASE CANVAS

Case Canvas กลางที่ทุกทีมต้องตอบ

ใช้ 10 หัวข้อนี้ร่าง Case ก่อนออกแบบ Solution โดยแนบ Evidence ID และสิ่งที่ยังไม่ยืนยันไว้กับคำตอบทุกข้อ

#หัวข้อเกณฑ์คำตอบที่ใช้ได้
1ชื่อ Case / ชื่อผลงานชื่อสื่อสารโจทย์และโอกาส ไม่อ้างผลเกินหลักฐาน
2ผู้ได้รับผลกระทบโดยตรงระบุบทบาทและบริบท แยกเจ้าของประสบการณ์จากผู้พูดแทน
3ปัญหาที่สังเกตได้บอกที่ไหน เมื่อไร ขั้นตอนไหน และความถี่เท่าที่มีหลักฐาน
4หลักฐานหลักEvidence ID, URL/ที่มา, วันที่ และตัวเลขหรือสิ่งที่เห็นจริง
5วิธีทำงานปัจจุบันอธิบาย workflow และว่าใครรับผิดชอบในแต่ละช่วง
6จุดติดขัดของวิธีเดิมระบุ failure mode พร้อมหลักฐาน ไม่ตั้งชื่อปัญหาแทนคำอธิบาย
7สาเหตุที่เป็นไปได้อย่างน้อยสองคำอธิบาย และสิ่งที่ยังไม่ยืนยัน/อาจหักล้าง
8Unmet needเขียนเป็นความต้องการของผู้เกี่ยวข้อง ยังไม่ผูกกับเทคโนโลยี
9Solutionอธิบายวิธีทำงาน คุณค่าใหม่ และการตอบ unmet need โดยตรง
10PoC / การทดลองสิ่งที่ทดลอง ผลที่ได้ ข้อจำกัด และการทดสอบรอบถัดไป

ระเบียนหลักฐานขั้นต่ำ

Evidence ID + วันที่URL + ผู้เผยแพร่ + ประเภทแหล่งคำกล่าวแยกจากสิ่งที่เห็นสถานที่ + ความเชื่อมั่นของขอบเขตบริบทฤดูกาล/นโยบาย/โครงการผู้ได้รับผลกระทบ + กลุ่มเสียงเบาข้อสนับสนุน/ข้อคัดค้านคำถาม/ผู้ให้ข้อมูล/วิธีวัดต่อ
05 / ESG & MEASUREMENT

ผลกระทบต้องผูกกับคนและตัวชี้วัด

เลือกเฉพาะมิติที่เกี่ยวข้องจริง ระบุผู้ได้ประโยชน์ วิธีเก็บข้อมูล และความถี่ อย่าใส่ครบสามด้านเพียงเพื่อให้ดูครอบคลุม

มิติตัวอย่างผลลัพธ์ที่ติดตามได้สิ่งที่ต้องระบุ
E · สิ่งแวดล้อมปริมาณทรัพยากร/ของเสีย คุณภาพสิ่งแวดล้อม พลังงานที่ใช้หน่วยวัด จุดเริ่มต้น วิธีเก็บ ความถี่ และขอบเขต
S · สังคมเวลา/ต้นทุนที่ลดลง การเข้าถึงบริการ รายได้หรือความปลอดภัยกลุ่มผู้ได้รับผลและผู้ที่อาจเสียประโยชน์
G · ธรรมาภิบาลความโปร่งใส ตรวจสอบย้อนกลับ การมีส่วนร่วม หรือความรับผิดชอบใครดูแลข้อมูล ตัดสินใจ และแก้ข้อร้องเรียน

ตัวอย่างคำถาม: วัดก่อนและหลังอะไร? จากใคร? ในช่วงเวลาใด? มีอะไรเปลี่ยนพร้อมกันจนทำให้ตีความผิดได้?

07 / REVIEW GATE

ประตูตรวจคุณภาพก่อนยืนยัน Case

ให้ทีมตอบ “ผ่าน / ยังไม่ผ่าน / ไม่มีข้อมูล” ทุกข้อก่อนล็อกโจทย์และก่อนส่งผลงาน

Challenge ตรงกับพื้นที่ และมีเหตุผลรองรับจากหลักฐาน
ปัญหาเขียนเป็นสิ่งสังเกตได้ ไม่สรุปสาเหตุล่วงหน้า
ระบุผู้ได้รับผลกระทบโดยตรง และตรวจกลุ่มเสียงเบา
ใช้หลักฐานมากกว่าหนึ่งชนิดและตรวจบริบทภายนอก
แยกฤดูกาล นโยบาย เงินสนับสนุน และเหตุพิเศษ
เข้าใจ workflow และวิธีแก้ที่มีอยู่ก่อนเสนอของใหม่
