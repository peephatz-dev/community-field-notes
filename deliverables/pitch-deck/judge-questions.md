# คำถามกรรมการและคำตอบตามหลักฐาน

ฉบับซ้อม 6 นาที · 15 ต.ค. 2569 · ตรวจแหล่งเต็มใน ../research/evidence-ledger.md

1. **ต่างจาก Aqua-IoT / Bubble FiT อย่างไร?**
   NECTEC มีระบบติดตามน้ำและ DO/ควบคุมเติมอากาศอยู่แล้วตามบทความ 2560/2563 เราเสนอวงจรตัดสินใจเรื่องไฟ วัดโหลด จัดลำดับสำรอง เทียบทางเลือก และตรวจผล ยังไม่อ้างนวัตกรรม sensor ที่ไม่เคยมีหรือราคาถูกกว่า (E10–E11)
2. **ทำไมแก้ไฟทั้งที่ปัญหาตะกอนดูใหญ่กว่า?**
   Data Pack รายงานไฟไม่เสถียรด้วย ทีมเลือกขอบเขตไฟเพื่อวัดและทดสอบจำกัดจุด ปัญหาน้ำและตะกอนต้องใช้ผู้เชี่ยวชาญและมาตรการอื่น ไม่อ้างว่าระบบสำรองไฟแก้ทั้งหมด (E01/E03)
3. **ยังไม่มีข้อมูลไฟแล้วจะทำทำไม?**
   สิ่งที่เสนอขั้นแรกคือเก็บข้อมูลที่ตรวจได้และสัมภาษณ์วิธีเดิม การลงทุนแบตหรือขยายอุปกรณ์ขึ้นกับผลนั้น ไม่ถือว่าไฟตกมีความถี่เท่าไรจากคำว่าบ่อย (E01)
4. **ใครต้องมีไฟสำรอง?**
   ยังต้องทำ load inventory กับเจ้าของเครื่องและผู้ดูแล P0–P3 เป็นสมมติฐานการออกแบบ ต้องให้ชุมชนเลือกโหลดและยอมรับผลต่อเครื่องที่พักได้ (E04/E16)
5. **ใครจ่าย?**
   ยังไม่มีผู้ซื้อ งบตกลง หรือ committed partner ต้องคุยรูปแบบเจ้าของอุปกรณ์ ค่าเปลี่ยนแบต ตู้ และการบำรุง ก่อนเสนอ capex/opex ที่ชุมชนรับภาระได้
6. **หาก UPS สำเร็จรูปก็พอ?**
   เลือก UPS ถ้าเข้ากับโหลดและต้นทุนตลอดอายุเหมาะกว่า การติดตามผลยังช่วยยืนยันความเพียงพอได้ ไม่ต้องสร้างฮาร์ดแวร์ใหม่ทุกกรณี (E13)
7. **ถ้า 4G หรือ gateway ดับ?**
   ในเดโม offline แยกจากไฟและ physical load ระบบจริงยังต้องออกแบบ local buffering/การกู้ข้อมูลและการบอกข้อมูลเก่า ทดสอบก่อนอ้างว่าใช้งานได้ขณะเครือข่ายขาด (E07)
8. **แยกไฟดับกับโหนด offline อย่างไร?**
   ใช้สัญญาณ source_voltage ที่ตรวจคุณภาพได้เทียบ last_seen/quality และยืนยันหน้างาน หากข้อมูลไฟขาดต้องระบุว่าไม่ทราบ ห้ามสรุปไฟดับจากเงียบอย่างเดียว (E07)
9. **วัดอะไรจริงแล้ว?**
   ยังไม่พบ logs ฮาร์ดแวร์หรือภาคสนามที่ยืนยันในเอกสาร มีผลซอฟต์แวร์ 52 ข้อและ browser capture จริง ข้อมูลในจอเป็นจำลอง (E06/E15)
10. **แบต 1.2 kWh มาจากไหน?**
    เป็นค่าตั้งต้นของตัวจำลอง ไม่ใช่ผล sizing หน้างาน อีกตัวอย่าง 469 Wh มาจาก 150 W สองชั่วโมง หาร 0.8×0.8 ยังต้องเผื่อการเสื่อม อุณหภูมิและกระแสเริ่มต้น (E05/E14)
11. **แจ้งเตือนแล้วใครทำต่อ?**
    ต้องตกลงคนรับเหตุ/ผู้สำรอง/เวลาและขอบเขตการตรวจซ่อม ตอนนี้ acknowledge และรายงานอยู่ในเครื่อง ยังไม่ส่งหน่วยงานจริง การทดลองต้องให้คนอ่านเหตุและบันทึกได้ (E08/E16)
12. **ชาวบ้านดูแลเองไหวไหม?**
    ยังไม่ทราบ ต้องทดสอบความเข้าใจ ภาระเปลี่ยนแบต ความชื้น/เกลือ อะไหล่ และผู้บำรุงรักษาโดยมีเจ้าของรับผิดชอบ ไม่ใช้ภาพมาสคอตแทน usability evidence
13. **ปลอดภัยพอหรือยัง?**
    ยังเป็นแนวคิด DC ต้องตรวจ rated load ฟิวส์ BMS สาย ตู้ ขั้วต่อ isolation การหยุดทดลอง และทดสอบโดยผู้มีคุณสมบัติก่อนประกอบ/ติดตั้ง เว็บไม่สั่ง mains จริง (E04/E15)
14. **ลดแจ้งเตือนผิด/แจ้งซ้ำอย่างไร?**
    ซอฟต์แวร์ dedup ตาม event ID และแยก sensor fault/offline/power การใช้จริงต้องกำหนด threshold, persistence/debounce, timestamp/seq และทดสอบ false positive กับ reference log ไม่มีอัตราความแม่นยำจริงให้กล่าวอ้าง (E07)
15. **เกณฑ์ GO/NO-GO คืออะไร?**
    GO เมื่อชุมชนยินยอม คนดูแลชัด โหลด/ข้อมูลเพียงพอ วงจรผ่านความปลอดภัย มีต้นทุนเทียบทางเลือก และผลทดลองตามเกณฑ์ร่วม หากยังไม่ปลอดภัย ไม่คุ้ม หรือดูแลไม่ได้ให้ปรับ/หยุด (E16)
16. **มีผลประหยัดเงินหรือช่วยชีวิตปลาเท่าไร?**
    ยังไม่มีการวัด จึงไม่ใส่เปอร์เซ็นต์ ผลตอบแทน หรือจำนวนปลาที่รอด ต้องทำ baseline และติดตามเทียบก่อนกล่าว (E03/E15)
17. **ทำไมไม่มี DO?**
    ยังไม่มี sensor และหลักฐานสอบเทียบ สีผิวน้ำหรือ salinity ใช้แทน DO ไม่ได้ ไม่แจ้งภัย DO จากค่าที่ไม่มี (E07)
18. **3D เหมือนพื้นที่จริงแค่ไหน?**
    รักษาความสัมพันธ์ฝั่ง ถนน ท่าเรือ อาคาร และกลุ่มกระชังจากภาพอ้างอิง แต่ไม่ใช่งานสำรวจ ไม่มีมาตราส่วน/ทิศเหนือ/จำนวนกระชังที่ยืนยัน อุปกรณ์ทุกจุดยังเสนอ (E09)
19. **ข้อมูลที่เซฟร่วมกันทั้งทีมไหม?**
    ตอนนี้ localStorage ใน browser และมีส่งออก JSON/CSV ยังไม่มี backend/cloud sync ต้องออกแบบสิทธิ์ เจ้าของข้อมูล retention และการรวมข้อมูลก่อนใช้หลายผู้ดูแล (E08)
20. **เกณฑ์แข่งขันและ Video ยืนยันแล้วหรือ?**
    เกณฑ์ห้าด้านเป็นสมมติฐานซ้อมตามคำยืนยันผู้ใช้ แบบฟอร์มฉบับล่าสุดยังต้องตรวจ ไกด์เดิมระบุวิดีโอคนถ่ายจริง 1–3 นาที ≤100 MB จึงทำแค่ shot list สำหรับคน ไม่สร้างวิดีโอ AI แทนข้อกำหนด

## คำถามที่ควรถามกลับในพื้นที่

ขอดูเหตุล่าสุดพร้อมเวลาและเครื่องที่ได้รับผล ถามสิ่งที่ทำจริงและค่าใช้จ่ายที่มีหลักฐาน ผู้ใดรับภาระดูแลได้ ข้อมูลใดเปิดให้ใช้ได้ และผลเสียแบบใดทำให้ควรหยุดทดลอง ไม่ตั้งคำถามนำว่าทุกบ้านต้องซื้อแบต
