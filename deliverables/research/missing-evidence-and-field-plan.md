# ข้อมูลที่ยังต้องยืนยัน และแผนทดลองขนาดเล็ก

สถานะ 15 ต.ค. 2569 · ข้อเสนอเพื่อหารือ ไม่ใช่การนัดหมายหรือพันธมิตรที่ตกลงแล้ว

## สิ่งที่ปักแล้วและเหตุผล

| การตัดสินใจของทีม | เหตุผล | เงื่อนไขที่ยังเปลี่ยนได้ |
|---|---|---|
| วัดไฟและโหลดก่อนเลือกอุปกรณ์สำรอง | Data Pack หน้า 6 รายงานไฟไม่เสถียร แต่ไม่มี frequency/voltage log การวัดช่วยแยกปัญหาฝั่งระบบไฟ โหลด และการสื่อสาร | อาจจบที่ให้หน่วยงานตรวจและซ่อม โดยไม่ต้องซื้อแบต |
| แยกไฟกับข้อมูล และ P0–P3 | ความผิดพลาดคนละชนิดต้องตอบสนองต่างกัน โหลดที่พักได้ช่วยรักษางบพลังงานในแบบจำลอง | รายการโหลดจริง ลำดับความสำคัญ และผู้อนุมัติต้องถามชุมชน |
| ทดลองวงจร DC ที่ป้องกันแล้วก่อน | ลดขอบเขตการทดลองให้ตรวจพิกัดได้ ไม่สั่งตัดไฟบ้านผ่านหน้าเว็บ | รุ่น board/fuse/BMS/driver/enclosure ยังต้องออกแบบและผ่านผู้มีคุณสมบัติ |
| ใช้ฉากอิงพื้นที่กับคำไทยสั้น | ช่วยให้ธุรกิจ ไอที และวงจรคุยตำแหน่ง/เหตุเดียวกัน | ต้องทดสอบความเข้าใจจริงกับผู้ใช้ ยังไม่มี usability result |
| มีเดโมเว็บและหลักฐานบนสไลด์ | รองรับหัวข้อ user flow/prototype ตามไกด์ทีม | จำนวนสไลด์ 10 และเวลา 6 นาทีเป็นฉบับซ้อมที่ผู้ใช้เลือก |

## สิ่งที่ยังขาด

| ลำดับ | ต้องหาอะไร | วิธีและผลส่งมอบ | เจ้าของ | ใช้ตัดสินใจ |
|---|---|---|---|---|
| 1 | ผู้ประสานงานที่ยินยอม จุดทดลองและเขตบริการไฟฟ้า | แบบยินยอม ขอบเขตการเข้าถึงข้อมูล รายชื่อผู้รับเหตุและผู้บำรุงรักษา (ไม่เผยเบอร์ส่วนตัว) | นาย / ข้าวฟ่าง, ท้องถิ่น TBD | GO/NO-GO การสำรวจ |
| 2 | วิธีเดิมก่อน ระหว่าง หลังเกิดเหตุ | สัมภาษณ์ผู้เลี้ยง ผู้ดูแล ช่างที่เกี่ยวข้อง บันทึกคำพูดและเวลาที่อ้างอย่างระมัดระวัง | ข้าวฟ่าง / นาย | ไม่ออกแบบ workflow แทนชุมชน |
| 3 | โหลดจริง W/VA/PF กระแสเริ่มต้น และเครื่องที่หยุดได้ | inventory พร้อมภาพ nameplate และการวัดโดยผู้มีคุณสมบัติ รวมชั่วโมงจำเป็น | โฟล์ค | เลือก UPS/แบต/แก้ระบบไฟ |
| 4 | แรงดันและช่วงเหตุไฟฟ้า | เลือก logger ที่เหมาะสม สอบเทียบ/เวลาเทียบกัน เก็บ baseline ช่วงเวลาที่ชุมชนเห็นว่าแทนการใช้งานได้ ระบุเวลาข้อมูลหาย | โฟล์ค / พี | ความถี่ ระยะเวลา ขอบเขตเหตุ ห้ามใช้ตัวจำลองแทน |
| 5 | ข้อมูลและระบบวัดน้ำเดิม | ขอเอกสารพิกัด sensor/เจ้าของข้อมูล/การสอบเทียบ/สิทธิ์เข้าถึงก่อนเชื่อม | บอส / ข้าวฟ่าง | ใช้ของเดิมได้หรือควรต่อเพิ่ม ไม่มี DO ยังไม่แจ้งภัย DO |
| 6 | หลักฐาน hardware bench test | รุ่น/serial/firmware/wiring, rated load, fuse/BMS/isolation, switch test, runtime log และ abnormal-case test | โฟล์ค | ทดสอบ DC ก่อนติดตั้ง ห้ามอ้างสลับไฟ AC สำเร็จ |
| 7 | BOM ราคา อายุแบต ค่าแรง ตู้ ค่าเชื่อมต่อ ค่าดูแล/เปลี่ยน | ใบเสนอราคา ≥ทางเลือกที่กำลังพิจารณา วันราคาและภาษี คำนวณ lifecycle cost จากช่วงเวลาที่ตกลง | นาย / โฟล์ค | เปรียบเทียบต้นทุนทั้งระบบ ไม่มี ROI ก่อนข้อมูลพอ |
| 8 | การแจ้งเตือนที่มีผู้รับผิดชอบ | ทดสอบ outage/offline/sensor fault ผู้รับอ่านเข้าใจและบันทึกสิ่งที่ทำ อัตราแจ้งผิดและเวลาแฝง | บอส / พี / ผู้ดูแล TBD | ปรับ threshold/debounce/last_seen |
| 9 | เกณฑ์แข่งขันและแบบฟอร์มล่าสุด | ตรวจเอกสารทางการ ภาษา เวลา PDF/VDO ขนาดไฟล์ การห้ามใช้ AI และสิทธิ์ภาพ | ข้าวฟ่าง / นาย | Submission gate ก่อนส่งจริง |

## Pilot 6 ขั้น

1. **สำรวจ**: 1–2 จุดที่เสนอ เลือกหลังชุมชนยินยอม พร้อมเจ้าของโหลดและผู้รับเหตุ แยกข้อเท็จจริงกับข้อสันนิษฐาน
2. **วัด**: baseline ไฟ โหลด การรับเหตุ และช่องว่างข้อมูล ใช้เครื่องมือเหมาะสมโดยผู้มีคุณสมบัติ หลีกเลี่ยงชาวบ้านแตะ mains
3. **วิเคราะห์**: จัดกลุ่มเหตุ ตรวจว่าควรแจ้งผู้ให้บริการ ตรวจสาย/อุปกรณ์ ใช้ UPS หรือป้องกันโหลดเฉพาะ รายงาน uncertainty
4. **ป้องกัน**: เลือกทางแก้ที่มีหลักฐานและความปลอดภัยเพียงพอ มีวิธีหยุด/ถอดระบบ ทดสอบบน bench ก่อน
5. **วัดผล**: ใช้ช่วงและโหลดที่เปรียบเทียบได้ รายงานเหตุทั้งหมด ข้อมูลหาย maintenance และผลเสียข้างเคียง
6. **ขยาย**: ตัดสินใจร่วมเมื่อผ่าน GO gate ถ้าไม่คุ้ม ดูแลไม่ได้ หรือไม่ปลอดภัย ให้แก้แบบ/หยุด ไม่ขยายอัตโนมัติ

## KPI ที่ต้องตกลงก่อนวัด

| KPI | นิยามและหน่วย | ข้อมูลที่ต้องใช้ | เจ้าของ |
|---|---|---|---|
| ความครบถ้วนหลักฐานเหตุ | จำนวนเหตุที่มีเวลา แรงดัน โหลด สถานะ และผู้ตรวจครบ / เหตุที่ reference logger ยืนยัน | reference log + event log + missingness | พี / โฟล์ค |
| เวลาคงโหลดสำคัญ | นาทีที่โหลดที่ชุมชนเลือกยังทำงานได้ตลอดเหตุ และช่วงที่หยุด | voltage/current/load state + runtime test | โฟล์ค |
| ต้นทุนตลอดอายุเทียบทางเลือก | บาทต่อช่วงอายุเดียวกัน รวมติดตั้ง เปลี่ยนแบต บำรุง และข้อมูล | BOM/quotes/อายุ/ค่าแรง/การเชื่อมต่อจริง | นาย |
| ผู้ดูแลใช้บันทึกรับเหตุได้ | รอบทดสอบที่ผู้ดูแลที่ตกลงไว้แปลเหตุและบันทึกการดูแลได้ / รอบที่ทดสอบ | usability tasks + บันทึกการรับเหตุ ไม่ใช้ click count แทน adoption | บอส / ข้าวฟ่าง |

เป้าหมายตัวเลข ระยะ baseline และผู้รับผิดชอบในชุมชนยัง TBD ใช้ agreed targets ก่อนเริ่ม ไม่กำหนดแล้วอ้างว่าทำสำเร็จ

## GO / NO-GO

GO เมื่อตกลงผู้รับผิดชอบ ข้อมูลและโหลดชัด วงจรผ่านการตรวจ/bench test มีต้นทุนตลอดอายุเทียบอย่างน้อยทางเลือกที่เหมาะสม และมีแผนถอดระบบ ไม่มีการเสี่ยงเพิ่มจากน้ำ/เกลือ/ไฟ

NO-GO หากข้อมูลไม่พอ แก้โดยซ่อมหรือ UPS สำเร็จรูปเหมาะกว่า ผู้ดูแลรับภาระไม่ได้ สิทธิ์ไม่ชัด หรือความปลอดภัยยังไม่ผ่าน ทบทวนก่อนลงทุน

## ผลกระทบที่วัดได้ภายหลัง

E: พลังงานใช้จริง อายุแบต ขยะอิเล็กทรอนิกส์และการรับคืน ยังไม่อ้างลดคาร์บอน
S: เวลาที่เครื่องจำเป็นทำงาน ความเข้าใจผู้ดูแล และภาระดูแล ยังไม่อ้างเพิ่มรายได้/ลดปลาตาย
G: เจ้าของข้อมูล สิทธิ์เข้าถึง การยินยอม ผู้รับเหตุ audit trail และการส่งออกข้อมูล
