PART A · PROBLEM PITCH

ช่วงพรีเซนต์ปัญหา

  • อธิบายเหตุการณ์ไฟตก/ไฟดับและผลต่อโหลดสำคัญในบริบทชุมชนหรือพื้นที่เพาะเลี้ยงปลา
  • แสดงว่าใครได้รับผล กระบวนการเดิมเป็นอย่างไร และเมื่อเกิดเหตุคนทำอะไรอยู่
  • แยกสิ่งที่ทีมมีหลักฐานแล้ว ออกจากสิ่งที่ยังเป็นสมมติฐานหรือรอสัมภาษณ์/ทดลอง
  • นายวางเรื่องและโครงสไลด์; ข้าวฟ่างช่วยแปลงบริบทและตรวจภาษา; ทุกคนเติมข้อเท็จจริงจากงานตัวเอง
PART B · SOLUTION PITCH

ช่วงพรีเซนต์ตัวแก้ปัญหา

  • เล่าว่า Community Energy Resilience Platform ทำอะไร: ไฟฟ้าเป็นแกนหลัก ข้อมูลความเค็มและอุณหภูมิใช้เฝ้าระวังความเสี่ยงด้านน้ำ
  • ไล่โครงสร้าง P0–P3 ทางเดินพลังงาน ข้อมูล เซนเซอร์ หน้าจอ และการแจ้งเตือน
  • แสดง User Flow หรือภาพระบบอย่างน้อยหนึ่งภาพ และอธิบายมาตรการไม่ให้เข้าใจผิดระหว่างไฟดับกับโหนดสื่อสารหาย
  • พูดให้ตรงว่าทำจริง / จำลอง / ยังเป็นแผน รวมข้อจำกัดและผลเสียข้างเคียง
เลือกระดับความพร้อมตามหลักฐาน: สถานะบนสไลด์ต้องสะท้อนการทำงานจริง ไม่ใช่เป้าหมายที่อยากไปให้ถึง; ถ้ายังไม่มีหลักฐานรองรับ ให้ระบุว่ายังไม่ยืนยันหรืออยู่ระหว่างศึกษา
เลือกหลังทีมรวมหลักฐานแล้วเท่านั้น เครื่องมือนี้บันทึกไว้ในเบราว์เซอร์นี้เพื่อช่วยเตือนการทำงาน
กติกากลางจากเอกสารทีม: ต้นแบบปัจจุบันเป็นแรงดันต่ำ ยังไม่ควบคุมไฟบ้านจริง; P1 วัดความเค็มและอุณหภูมิ ไม่ได้วัดออกซิเจนในน้ำโดยตรง; โซลาร์ แบตเตอรี่ขนาดใหญ่ และวงจรสำรองอาคารเป็นแนวทางต่อยอด ไม่ใช่ความสามารถที่ยืนยันแล้ว
WHO DOES WHAT

แบ่งงานรายคน พร้อมของที่ต้องส่ง

ทุกคนเริ่มทำส่วนของตัวเองพร้อมกันได้ ไม่ต้องรอให้สไลด์หลักเสร็จ ส่งเป็นร่างอ่านรู้เรื่อง พร้อมหลักฐานและสถานะจริง แล้วทีมค่อยนำไปประกอบ

น

นาย · เจ้าของเรื่องและภาพรวมระบบ

รับผิดชอบหลัก: โครงสไลด์ ปัญหา ภาพรวมและขอบเขต P0–P3

ต้องส่ง

  • ร่างลำดับสไลด์ 7–10 หน้าและข้อความสั้นสำหรับแต่ละหน้า
  • คำอธิบายปัญหาและผลกระทบที่ตรวจที่มาได้ ร่วมกับข้าวฟ่าง
  • ภาพรวมระบบ บทบาท P0–P3 และทางเดินพลังงาน/เหตุฉุกเฉิน
  • ระบุให้ชัดว่าส่วนไหนทำจริง จำลอง หรือวางแผนต่อยอด
ฟ

โฟล์ค · เซนเซอร์และวงจร

รับผิดชอบหลัก: จุดวัด หลักการต่อวงจร ความปลอดภัย และขอบเขตการวัด

ต้องส่ง

  • แผนภาพเซนเซอร์/วงจรและคำอธิบายว่าแต่ละตัววัดอะไร
  • ตาราง “วัดโดยตรง / อนุมาน / ยังวัดไม่ได้” พร้อมเหตุผล
  • ข้อจำกัดการต่อใช้งานจริง การป้องกันสัญญาณรบกวน และภาพต้นแบบที่ทำจริง
  • สถานะผลทดสอบจริง หรือระบุว่ายังไม่มีผลทดสอบ
พ

พี · ข้อมูล หน้าจอ กราฟ และแจ้งเตือน

รับผิดชอบหลัก: สิ่งที่ผู้ใช้เห็นและวิธีอ่านสถานะ

ต้องส่ง

  • ตัวอย่างหน้าจออย่างน้อยสถานะปกติ เฝ้าระวัง วิกฤต ออฟไลน์ และเซนเซอร์ผิดปกติ (ทำเท่าที่ต้นแบบรองรับ)
  • ตัวอย่างกราฟไฟตก/ดับ ช่วงใช้ไฟสำรอง และแนวโน้มความเค็ม/อุณหภูมิ
  • กติกาและข้อความแจ้งเตือนที่บอกเหตุ โหนด เวลา และสิ่งที่ควรทำ
  • ระบุว่าหน้าจอหรือกราฟใดเชื่อมข้อมูลจริง และอันใดเป็น mockup
บ

บอส · การส่งข้อมูลและสถานะโหนด

รับผิดชอบหลัก: รูปแบบข้อความ P1–P3 ไป P0 และความทนทานของการส่ง

ต้องส่ง

  • ตัวอย่างข้อความที่มี node_id, seq, timestamp, ค่าเซนเซอร์/ไฟฟ้า และสถานะที่จำเป็น
  • แผนรอบส่ง การส่งทันทีเมื่อเกิดเหตุ การตอบรับและส่งซ้ำ
  • กติกาเก็บข้อมูลชั่วคราวและส่งย้อนหลังเมื่อสื่อสารกลับมา (ถ้ามีในขอบเขตต้นแบบ)
  • นิยามสถานะโหนด และตัวอย่างแยก “ไฟดับ” ออกจาก “P0 ไม่ได้รับข้อมูล”
ข

ข้าวฟ่าง · เรียบเรียงและตรวจหลักฐาน

รับผิดชอบหลัก: ทำเรื่องเทคนิคให้อ่านเข้าใจ ตรวจผลจริง ข้อจำกัดและผลกระทบ

ต้องส่ง

  • คำอธิบายระบบภาษาง่ายและตรวจความต่อเนื่องระหว่างหน้าสไลด์
  • ตารางเกณฑ์ยืนยันผล: พิสูจน์แล้ว / สาธิตด้วยการจำลอง / ยังทำไม่ได้
  • รายการหลักฐาน ภาพ/กราฟจากเจ้าของงาน ข้อจำกัด ผลต่อชุมชนและคำถามที่ยังต้องตอบ
  • ตรวจข้อความสไลด์ให้ไม่กล่าวอ้างเกินการทดลองที่มี
ทีม

งานที่ต้องช่วยกันทำ

ทำหลังแต่ละคนส่งร่าง หรือทำคู่ขนานในส่วนที่ไม่ต้องรอระบบรวม

ต้องช่วยกัน

  • ยืนยันว่าโจทย์ปัญหาและผู้ได้รับผลมาจากข้อมูล/การคุยกับผู้ใช้ ไม่ใช่คาดเดาแทนชุมชน
  • เตรียมสถานการณ์สาธิต: ปกติ → ไฟตก/ดับ → ไฟสำรอง/จัดลำดับโหลด → แจ้งเตือน → ฟื้นระบบ (แยกสิ่งจำลองออก)
  • เอาภาพต้นแบบ หน้าจอ บันทึกเหตุการณ์และผลผ่าน/ไม่ผ่านมารวมกัน
  • ตรวจชื่อ P0–P3 คำศัพท์ ตัวเลข หน่วย และขอบเขตให้ตรงกันทุกหน้า

ชุดส่งเข้ากลาง (ทุกคนใช้รูปแบบเดียวกัน)

  • ชื่อส่วนและเจ้าของงาน · ร่างข้อความ/ภาพ · แหล่งข้อมูลหรือรูปถ่ายต้นฉบับ
  • สถานะ: ทำจริง / จำลอง / mockup / แนวคิดต่อยอด · ผลทดสอบพร้อมวันและเงื่อนไขถ้ามี
  • ข้อจำกัดและคำถามที่ยังไม่มีคำตอบ — อย่าเติมค่าหรือผลทดลองที่ยังไม่ได้วัด

โครงสไลด์ที่รวมงาน 12 หัวข้อให้เล่าเป็นเรื่อง

เอกสารทีมแจกหัวข้อไว้ละเอียด 12 ข้อ แผนนี้รวมส่วนที่ต่อเนื่องกันเพื่อให้อยู่ในช่วง 7–10 หน้า โดยยังครอบคลุมปัญหา บริบท วิธีเดิม ตัวแก้ปัญหา User Flow หลักฐาน ข้อจำกัด ผู้เกี่ยวข้อง และแผนทดลอง

หน้าจังหวะเรื่องสิ่งที่ใส่ให้คนดูเข้าใจคนทำหลัก / ช่วยกันชิ้นงานก่อนรวม
1Executive Summaryชื่อ Community Energy Resilience Platform, ปัญหาที่เลือกตอบ, คำตอบหนึ่งประโยค, สมาชิกและสถานะต้นแบบจริงนาย / ข้าวฟ่างตรวจข้อความข้อความสรุปไม่เกิน 3 ประโยคและภาพระบบ
2ปัญหาและผู้ได้รับผลกระทบเหตุไฟตก/ดับในบริบทที่ศึกษา, ใคร/โหลดใดได้รับผล, หลักฐานและปี, สิ่งที่ยังต้องยืนยันกับผู้ใช้นาย + ข้าวฟ่าง / ทุกคนส่งหลักฐานแผนที่หลักฐานและผลกระทบโดยไม่อ้างความชุกเกินข้อมูล
3บริบทและวิธีเดิมก่อนเกิดเหตุ–ระหว่างเหตุ–หลังเหตุ ผู้ใช้รับรู้และจัดการอย่างไร; ระบุ workflow ปัจจุบันตามข้อมูลจริงข้าวฟ่างเรียบเรียง + นายวางเรื่อง / ทีมช่วยยืนยันแผนภาพ workflow เดิม หรือบอกช่องว่างข้อมูลหากยังไม่ได้สัมภาษณ์
4แนวทางแก้และโครงสร้างไฟฟ้าเป็นแกนหลัก; P0 เป็นศูนย์กลาง, P1 น้ำและไฟ, P2 โหลดจำเป็น, P3 โหลดทั่วไป; ความเค็ม/อุณหภูมิใช้เฝ้าระวังความเสี่ยงน้ำนาย / โฟล์ค บอส พี ให้ข้อมูลBlock diagram P0–P3 พร้อมลูกศรไฟฟ้า/ข้อมูล
5User Flow + Mockup/Diagramไฟตก/ดับ → ตรวจข้อมูล → ใช้ไฟสำรองตามขอบเขตที่ทำ → รักษาโหลดสำคัญ → แจ้งเตือน → ฟื้นระบบ; แยกกรณีสื่อสารหายนาย + พี + บอส / ทั้งทีมตรวจคำอธิบายอย่างน้อย 1 ภาพ user flow, หน้าจอ หรือ prototype ที่อ่านได้
6เซนเซอร์และการทำงานจุดวัด หลักการวงจร สิ่งที่วัดได้ตรง ๆ สิ่งที่อนุมาน และสิ่งที่ต้นแบบยังวัดไม่ได้โฟล์ค / ข้าวฟ่างจัดคำให้อ่านง่ายภาพวงจร/เซนเซอร์พร้อมป้ายชื่อและขอบเขต
7ข้อมูล หน้าจอ และแจ้งเตือนตัวอย่างข้อมูล, การส่ง P1–P3 ถึง P0, กราฟ/หน้าจอ, ความหมายของ online/offline และเหตุการณ์พี + บอส / นายเชื่อมกับระบบตัวอย่าง payload + หน้าจอ/กราฟ และกติกาแจ้งเตือน
8PoC / ผลทดลอง / ข้อจำกัดภาพต้นแบบและผลที่วัดได้, สิ่งที่จำลอง, ผ่าน/ไม่ผ่าน, ข้อจำกัดแรงดันต่ำ; ยังไม่ควบคุมไฟบ้านจริงเจ้าของการทดลองทุกคน / ข้าวฟ่างรวมเกณฑ์ตาราง “ทำจริง–จำลอง–ยังไม่ได้ทำ” พร้อมหลักฐานลงวันที่
9ผู้เกี่ยวข้อง, ESG, ทดลองและต่อยอดใครต้องร่วมทดลอง, วิธีเก็บ feedback, ความปลอดภัยและผลข้างเคียง, ตัวชี้วัด, แผนถัดไป; ระบุโซลาร์/แบตจริงเป็นอนาคตถ้ายังไม่ได้ทำข้าวฟ่าง + นาย / ทุกคนช่วยตรวจความเป็นไปได้แผนทดลองสั้น ๆ ผู้รับผิดชอบ ความเสี่ยงและตัวชี้วัด
